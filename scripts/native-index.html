Linux

Installation requires native Ubuntu 24.04/26.04 x86-64, systemd, Bash and Python 3.10+. The standalone script embeds its backend. ARM64 installation is deferred; explicit diagnostics remain available.

curl -fL https://motebus.github.io/download/agpc.sh -o agpc.sh
bash ./agpc.sh install --dry-run
sudo bash ./agpc.sh install
agpc status

The core includes uChat. Install optional MDESK, MLINK and SS-WebOS after the core:

curl -fsSL https://motebus.github.io/download/agpc-apps.sh | sudo bash

Codex CLI is managed separately. These installers do not download, install or update it.

Windows

PowerShell 7.4+ is used when available; otherwise the launcher uses the matching Windows PowerShell 5.1 host shipped with Windows 10/11. Download the executable for your CPU. The preview EXEs are unsigned.

curl.exe -fL https://motebus.github.io/download/agpc.exe -o agpc.exe
.\agpc.exe
.\agpc.exe install -RuntimeManifest C:\ProgramData\AGPC\runtime-manifest.json
.\agpc.exe status -Json

Running the executable with no command invokes the overall installer. On ARM64, download agpc-arm64.exe instead and run the same command. The overall installer verifies the approved native runtime manifest, installs the Mote services through Windows SCM and enables OpenSSH. It does not use WSL or Debian packages. The manifest is required and is intentionally fail-closed when runtime bundles are not published.

Mac (M-series)

Native ARM64 controller preview. Docker Desktop must use Apple Virtualization framework with Rosetta enabled. Only MoteBus + DC run inside its Linux VM.

curl -fL https://motebus.github.io/download/agpc -o agpc
chmod +x agpc
./agpc version
./agpc init
./agpc sphere start

Run as your normal user. Full startup requires the remaining native owner binaries configured in ~/Library/Application Support/AGPC/agpc.json. This download contains the controller only. Apple Developer ID signing and notarization are pending.

P Channel — Browser execution

AGPC now includes local browser operations through Playwright + Chrome DevTools Protocol. Core agent execution is B / SSH + M / MCP + P / CDP + R / RDP. C remains Content.

agpc browser setup
agpc browser doctor
agpc browser plan /absolute/policy.json /absolute/request.json
agpc browser run /absolute/policy.json /absolute/request.json

Linux agpc install includes pinned private Node, Chrome and Playwright setup for the invoking sudo user; root automation uses --browser-user USER. Run browser commands as the normal user. Windows/macOS require native Node.js 22+, npm and architecture-matched Chrome/Chromium; browser setup installs the pinned Playwright engine. An expiring policy grants explicit origins, actions and file roots; mutations require verification. Each request uses a fresh browser profile, with metadata audit and replay rejection. See the versioned release archive README for policy/request examples. Remote P admission and native Windows/Mac browser acceptance remain pending.

Codex or the Agent chooses headless by default and headed when the task needs visibility or human interaction. Both use a dedicated Agent Chrome profile. The selected mode and reason appear in the session audit. Schema-v2 policies can restrict the allowed modes. Existing browser attachment requires stronger S authorization and remains unavailable in this preview.

Full-desktop intent produces a separate XRDP or physical RDP plan; it does not open a desktop session. A denied browser action never triggers automatic fallback.

RDP desktop clients

Linux installs two FreeRDP menu entries: FreeRDP(xrdp) and FreeRDP(physical). Both use FreeRDP at 1920×1080. Physical uses target port 3389 and XRDP uses 3390; both can run concurrently. XRDP is the default mode; physical mode requires a separately enabled and authorized desktop backend.

rdp workstation.mote
rdp workstation.mote --desktop physical
rdp workstation.mote --show-plan

Register the target and its native certificate in your private client configuration first. Unconfigured targets and inactive modes fail visibly. Native Remmina stays installed with RDP, SSH/SFTP and keyring support; open Remmina from its app-menu entry to manage saved profiles. The FreeRDP launchers have no Remmina submenu actions. Existing profiles and credentials are preserved. For upgrades, follow the profile and listener migration steps in the versioned release.

Preview scope

Linux installation verifies pinned runtime packages, preserves existing conffiles and records the result. Windows uses the same native PowerShell overall-installer backend in both CPU artifacts; it requires an approved native runtime manifest and does not claim Ready from service installation alone.

Run diagnostics without elevation. Package installation does not establish AGPC Ready: S-channel enrollment, application health, peer connectivity and RDP-over-Mote acceptance remain required. Linux enables xrdp with TLS on loopback. Existing xrdp ports are preserved; a new XRDP server uses port 3390, with Physical RDP reserving 3389. Use --rdp-port PORT to choose another port. Existing GNOME access is preserved. A compatible Xorg desktop session is required. RDP uses an independent Mote channel, without SSH forwarding, with v2 mode selection for remote loopback Physical 3389 and XRDP 3390. Each mode uses its own local listener. RDP credentials remain with the native client/server; Agent screen/input APIs, S-channel integration and full AGPC RDP acceptance remain pending. The Mac download contains only the ARM64 controller; native owner artifacts and full runtime acceptance remain pending.
